01 · About

Testing from user story to production.

I test a cloud ERP and two synced desktop apps (Store and POS) inside the core product squad, from user stories to bug verification, staging regression and the production release in Azure DevOps.

My daily work is REST API testing in Postman and data synchronization checks, confirmed through application logs and direct SQL queries. I use GitHub Copilot to draft test cases from pull requests, then review them and write the missing coverage myself.

Before QA, I spent almost three years in service desk and technical support at the same company. That is where I learned how real users break software.

02 · Case

A bug I found before release

During support, I was picked to run pre-release validation on a major update. I went straight to the riskiest change.

Bug ● High risk · tax compliance ✓ Caught pre-release

Invoice sync reports success but leaves the invoice pending

Found before release · reported with a reproducible scenario

Flow tested
NF-e (Brazilian electronic tax invoice) syncing from the Store app to the ERP while pending tax authorization.
Defect 1
Retransmission of the invoice failed in the ERP.
Defect 2
The authorization sync was logged as successful, but the invoice status was never updated.
Outcome
Reported before the release, with steps to reproduce.
